# 小组件可选额度漏项检查

本次针对编辑页「显示内容」只出现「每周」的问题检查数据链。没有添加趋势、余额等 AI-Usage 不提供的可选额度，也没有修改布局、风格、App 页面、应用图标、2×1 布局、Wear OS 或共享模块。

## 已复现并修正的差异

对照 AI-Usage `providers/codex/usage-parser.ts` 的 `extractCodexWindows`：

- 附加额度可以在顶层 `additional_rate_limits`，也可以位于 `rate_limit.additional_rate_limits`。旧解析器只读顶层，导致嵌套的 Spark 额度丢失。
- 支持 `rateLimit`、`primaryWindow`、`secondaryWindow` 容器别名；旧解析器只读下划线形式。
- 在主额度缺项时，也读取直接列出的 `five_hour`、`weekly`、`monthly` 窗口；相同窗口仍优先采用原主额度。

只扩大手机端解析器对这些响应结构的识别，继续使用原快照模型和小组件选项规则。编辑器没有硬编码添加虚构额度；如果响应确实只有周额度，可选项仍只有每周。

真实编辑页回归测试还发现英文「Show % symbol」通过格式化函数读取会崩溃，已改用普通资源读取。中文文案及控件设计未变。

## 验证与边界

新增测试先在旧解析器上执行，四个数据格式测试中三个失败，周额度单项对照通过。修复后这些测试通过，并增加从响应解析、缓存保存、启动真实编辑页、勾选两个 Spark 窗口到保存选择的完整验证。

截图无法证明手机接口是否返回了上述附加额度，本次不能据此断言已定位实机根因。覆盖安装后需要在首页刷新一次，重新解析服务端响应；旧缓存无法自行找回过去被丢弃的字段。

验证结果：核心自测通过，Android 单元／界面测试 46 项通过，手机 lint 及签名 release 构建通过。
